## 1. 카테고리 정보

### 1.1 카테고리 설계 원칙

1. **6개를 넘지 않는다.** 홈 스탬프 카드 한 화면에 들어가야 한다.
2. **공간이 아니라 문제군으로 나눈다.** "침실"이 아니라 "침구·빨래". 사용자는 방이 아니라 겪는 문제로 인식한다.
3. **모든 카테고리에 최소 하나의 외주 경로가 있어야 한다.** 직접 해결만 가능한 카테고리는 수익 루프가 닫히지 않는다.

## 2. 청소 도구·방법 정보

### 2.1 가이드 콘텐츠 표준 구조

블로그 글처럼 길면 안 된다. **현장에서 한 손으로 스크롤하며 따라 할 수 있어야 한다.**

```text
1. 먼저 확인할 것    ← 표면 소재, 원인 구분
2. 준비물           ← 보유 여부 체크 가능
3. 단계별 청소       ← 3~6단계, 각 단계 1문장
4. 잘 안 지워질 때   ← 2차 시도
5. 하면 안 되는 것   ← ⚠️ 상단에도 중복 노출
6. 다음부터 덜 생기게 하는 법
7. [해결 완료] 버튼   ← 누르면 주기 자동 등록
```

**필드 정의 (Guide 스키마)**

| 필드 | 설명 |
|---|---|
| issue_name | 물때, 곰팡이, 배수구 냄새 등 |
| location | 발생 위치 |
| cause | 습기, 환기 부족, 세제 잔여물, 음식물 찌꺼기 등 |
| difficulty | 쉬움 / 보통 / 어려움 |
| duration_min | 5 / 15 / 30 / 60+ |
| tools[] | 세제, 솔, 장갑, 마스크, 천 |
| steps[] | 단계별 절차 |
| warnings[] | 혼합 금지, 환기, 소재 손상, 피부 보호 |
| prevention | 재발 방지 |
| default_cycle_days | 해결 후 다음 점검 시점 |
| related_products[] | 도구 카드 |
| related_vendors[] | 업체 카드 |
| pro_threshold | "여기부터는 전문가" 기준선 |

### 2.2 안전 정보 — 타협 불가 항목

**모든 가이드 상단에 고정 노출한다. 캐릭터 톤이 아닌 시스템 톤으로 쓴다.**

| 금지 조합 | 이유 |
|---|---|
| **염소계(락스) + 산성(구연산, 식초, 물때 제거제)** | 유독한 염소가스 발생. 밀폐된 욕실에서 특히 위험 |
| **염소계 + 암모니아계** | 클로라민 가스 발생 |
| 서로 다른 세제 무작정 혼합 | 예측 불가 반응 |

| 소재 | 쓰면 안 되는 것 |
|---|---|
| 대리석·천연석 | 산성 세제 (구연산, 식초, 물때 제거제) — 표면이 부식된다 |
| 알루미늄 | 강알칼리 세제 |
| 코팅 프라이팬 | 금속 수세미, 연마제 |
| 에어컨 냉각핀 | 강한 세정제 원액 — 부식 위험 |
| 원목 마루 | 다량의 물 |

**필수 안내**
- 환기: 락스류·강산성 세제 사용 시 창문 개방 + 환기팬
- 보호구: 고무장갑 필수, 스프레이형은 마스크 권장
- 어린이·반려동물: 세제 사용 중 접근 차단, 건조 후 출입
- **확실하지 않은 정보는 단정하지 않는다.** "~일 수 있어요"로 쓴다

### 2.4 도구 추천 규칙

1. **가이드와 무관한 상품을 끼워 넣지 않는다.**
2. **왜 필요한지 한 줄로 설명한다.** ("줄눈은 좁아서 일반 솔이 안 들어가요")
3. 제휴·광고·스폰서는 배지로 명시한다.
4. 사용자가 보유 도구를 체크하면 중복 추천을 줄인다.
5. **구매하지 않고도 되는 대체 방법을 반드시 함께 제시한다.** (2.3의 '대체 방법' 컬럼)

> 5번은 신뢰의 핵심이다. 대체 방법을 제시하는 앱의 추천만 사용자가 믿는다.

## 3. 주기 계산 로직

### 3.1 설계 제약

- 사용자는 **아무것도 등록하지 않는다.** 첫 화면부터 상태가 계산되어 있어야 한다.
- 근거를 설명할 수 없는 합성 점수는 쓰지 않는다.
- 집이 실제로 더러운지는 **모른다.** 우리는 경과 시간과 사용자 입력으로 추정할 뿐이며, 이를 UI에서 숨기지 않는다.

### 3.2 기준선(Baseline)

```text
last_done_at 초기값 = User.created_at
```

가입일을 '집이 마지막으로 정돈된 날'로 **가정**한다. 사용자가 첫 해결을 하는 순간부터는 실제 데이터로 대체된다.

> 온보딩 문구: "가입한 오늘을 기준으로 세기 시작할게요. 이미 오래된 항목이 있다면 스탬프에서 바로 바꿀 수 있어요."

### 3.3 상태 판정

```text
elapsed        = today - last_done_at              (경과일)
cycle          = effective_cycle_days              (유효 주기, 3.4 참조)
ratio          = elapsed / cycle

상태:
  정상 (초록)   ratio < 0.7
  임박 (노랑)   0.7 ≤ ratio < 1.0
  지연 (분홍)   ratio ≥ 1.0
  위험 (별도)   사용자 증상 입력 발생 시 즉시 (냄새/곰팡이/벌레/막힘)
```

- **탭 가능한 항목은 '지연'뿐이다.** 정상 항목을 누르게 하는 건 가짜 상호작용.
- '임박'은 스탬프에 표시되지만 액션은 알림 채널로만 열린다.
- '위험'은 ratio를 무시하고 최상단 노출 + 전문가 옵션 동시 제시.

### 3.4 유효 주기 계산

```text
effective_cycle_days
  = base_cycle_days
  × lifestyle_multiplier
  × season_multiplier
  × user_override
```

#### base_cycle_days
카테고리별 기본값 (1.3 표의 권장 주기 중앙값). 이슈 단위로 정의된다.

#### lifestyle_multiplier (온보딩 없이, 사용 중 수집)
| 조건 | 배수 | 적용 대상 |
|---|---:|---|
| 반려동물 있음 | ×0.7 | 침구, 바닥, 해충 |
| 거주 인원 2인 이상 | ×0.8 | 욕실, 주방, 쓰레기 |
| 배달음식 주 4회 이상 | ×0.7 | 쓰레기, 해충 |
| 요리 주 3회 이상 | ×0.8 | 주방 |
| 원룸·환기 취약 | ×0.8 | 욕실 곰팡이 |

> 이 정보는 온보딩에서 묻지 않는다. 해결 플로우 중 자연스럽게 수집하거나(예: 해충 이슈 선택 시 "반려동물이 있나요?"), 사용자가 설정에서 켠다.

#### season_multiplier
| 시기 | 대상 | 배수 |
|---|---|---:|
| 6~8월 (장마·고온) | 욕실 곰팡이, 해충, 쓰레기 | ×0.6 |
| 12~2월 (결로) | 창틀, 곰팡이 | ×0.8 |
| 4~5월 | 에어컨 (계절 알림 트리거) | 별도 |

#### user_override
사용자가 주기 보드에서 직접 조정한 값. **항상 최우선.**

### 3.5 해결 후 주기 재등록

```text
[해결 완료] 탭
  → ResolutionLog 생성 (issue_id, method: SELF|PARTNER|SUBSCRIPTION, done_at)
  → RoutineTask upsert
       last_done_at = done_at
       next_due_at  = done_at + effective_cycle_days
  → CategoryStatus 즉시 재계산 → 스탬프 반영
```

**확인 절차 없음.** "다음 주기로 등록할까요?"를 묻지 않는다. 해결했다는 사실 자체가 등록 트리거다.

### 3.6 방식별 주기 보정

| 해결 방식 | 다음 주기 |
|---|---|
| SELF (직접) | base 주기 그대로 |
| PARTNER (1회 외주) | base 주기 × 1.2 — 전문 청소는 더 깨끗하게 오래 간다 |
| SUBSCRIPTION (정기 구독) | 해당 카테고리는 **상시 완료 상태로 고정**. 구독 해지 시 재계산 |

### 3.7 스누즈와 재시작

- 사용자가 '미루기'를 누르면 `next_due_at += 3일`. 최대 2회.
- 3회째부터는 미루기 대신 **"이 작업 주기를 늘릴까요?"** 또는 **"정기 서비스를 볼까요?"** 를 제안한다.
- **반복적으로 밀리는 항목은 실패가 아니라 신호다.** 주기가 틀렸거나 외주 대상이라는 뜻.
- 30일 이상 미접속 후 복귀 시: 모든 지연 항목을 나열하지 않는다. **가장 빠른 것 하나만** 보여주고 "오늘부터 다시 세어볼게요"로 시작한다.

### 3.8 추천 우선순위 점수 (내부용)

홈에서 어떤 지연 항목을 위에 놓을지 결정하는 정렬 기준이다. **사용자에게 점수로 노출하지 않는다.**

```text
priority_score =
    지연 정도(ratio)         × 0.30
  + 위생 민감도(고정 가중치)   × 0.25
  + 방치 시 난이도 상승폭      × 0.20
  + 짧은 소요시간(역가중)      × 0.15
  + 외주 가능 여부            × 0.10
```

'방치 시 난이도 상승폭'을 넣는 이유: 곰팡이는 시간이 지날수록 급격히 어려워지고, 바닥 먼지는 그렇지 않다. 같은 5일 지연이라도 곰팡이를 먼저 보여줘야 한다.

### 4.2 업체 리스팅 필수 항목

업체 카드에는 다음이 모두 있어야 한다. 하나라도 없으면 카드를 만들지 않는다.

- 서비스 가능 지역
- 기본 가격과 **추가 비용 발생 조건** (성수기 할증, 층고, 오염도)
- 가능 날짜/시간
- 평균 소요 시간
- 제공 범위 / **제외 범위**
- 후기와 별점
- 취소 정책
- 보험·보상 정책
- **제휴 여부 (배지)**

### 4.3 업체 품질 관리

한 번의 나쁜 경험이 앱 신뢰를 무너뜨린다. 중개자는 소개한 순간부터 책임의 일부를 진다.

| 항목 | 기준 |
|---|---|
| 등록 심사 | 사업자등록, 보험 가입, 최소 후기 수 |
| 서비스 범위 표준화 | "에어컨 청소"가 업체마다 다른 것을 우리 쪽에서 통일 표기 |
| 가격 표시 기준 | 공식가 노출. 추가비용 조건 명시. 확정 할인처럼 말하지 않음 |
| 후기 검증 | 실제 예약 기록과 연결된 후기만 노출 |
| 클레임 처리 | 접수 창구 명시, 24시간 내 1차 응답 |
| 모니터링 | 재예약률, 만족도, 클레임률. 임계치 미달 시 노출 강등 |

### 4.4 예약 흐름

```text
1. 사용자가 지연 항목 탭 → 세부 이슈 선택
2. 가이드에서 직접 해결 난이도 확인
3. STEP 4에서 [직접 하기] / [맡기기] / [나중에] 선택
4. 맡기기 → 업체 카드 비교 (가격, 지역, 후기, 제휴 배지)
5. 외부 예약/문의 연결 (MVP는 딥링크. 자체 결제 없음)
6. 해당 작업은 "외주 예약됨" 상태로 전환
7. 완료 후 만족도·사진 후기 → 동일 이슈 다음 점검 주기 자동 등록
```
