# 3. 마이 화면

작업 순서: 3번째
의존성: 00-foundation, 02-selection (저장한 셀렉션 화면에서 셀렉션 카드 컴포넌트 재사용)
연결 백엔드 문서: `04-home-summary.md`(GET /me/summary), `03-completion.md`(GET /completion-logs), `05-selection.md`(GET /me/saved-selections, DELETE save)
참고 요구사항: MY-01~12
참고 디자인: design-direction.md 9장

## 3.1 마이의 역할

모든 기록을 한 화면에 펼치는 곳이 아니라, 사용자의 청소 리듬을 요약하고 필요한 상세 메뉴로 들어가는 허브다.

## 3.2 마이 첫 화면 구성

1. 프로필 요약 (이름/닉네임)
2. 청소발자국 요약: 이번 달 완료 수, 관리 카테고리 수, 저장 셀렉션 수 (`GET /me/summary`의 `stats`)
3. 최근 12주 시각화 (`weeklyFootprints`, `level` 0~3 단계로 표현)
4. 메뉴 목록 (00-foundation의 메뉴 행 컴포넌트 사용)

```text
완료 히스토리       이번 달 8개 >
저장한 셀렉션       3개 담아둠 >
주기 관리           6개 사용 중 >
내 정보             >
```

`알림 설정` 메뉴는 이번 범위에서 제외한다(Notification 백엔드 도메인 없음).

## 3.3 마이 첫 화면에서 분리한 것

다음은 마이 첫 화면에 직접 펼치지 않고 메뉴 진입 후 별도 화면에서 보여준다.

- 최근 완료 전체 목록 (`MY-05` → 완료 히스토리 화면)
- 저장한 셀렉션 카드 목록 (`MY-09` → 저장한 셀렉션 화면)

## 3.4 완료 히스토리 화면

구성:

- 월별 필터
- 카테고리 필터
- 완료 기록 리스트 (`GET /completion-logs`, `from`/`to` 쿼리로 월별 필터 구현)
- 빈 상태 문구: `아직 기록이 없어요` / `처음 한 일을 남기면 다음 주기는 제가 기억할게요`

각 항목은 카테고리명과 완료일을 표시한다(MY-06). 홈에서 완료한 기록은 이 목록에 즉시 반영되어야 한다(MY-07) — `GET /completion-logs`를 다시 호출하거나 홈에서 받은 로그를 로컬 상태에 append한다.

## 3.5 저장한 셀렉션 화면

- `02-selection.md`의 셀렉션 카드 컴포넌트를 그대로 재사용한다.
- 카드에서 저장 해제 액션을 명확히 둔다(MY-11).
- 빈 상태 문구: `담아둔 셀렉션이 없어요` / `괜찮아 보이는 상품이나 서비스를 담아두면 여기서 다시 볼 수 있어요`

저장 상태 변경(저장/해제)은 셀렉션 목록, 상세, 마이 어디서 실행하든 세 화면 모두에 일관되게 반영되어야 한다(MY-12). 전역 상태(예: React Query 캐시 무효화, 전역 store)로 관리하는 것을 권장한다.

## 3.6 완료 기준

1. 마이 첫 화면이 프로필/요약/12주 시각화/메뉴 4개로만 구성되고, 리스트가 길게 펼쳐지지 않는다.
2. 완료 히스토리 화면에서 월별·카테고리 필터로 기록을 조회할 수 있다.
3. 저장한 셀렉션 화면에서 셀렉션 카드가 재사용되고, 저장 해제가 바로 반영된다.
4. 저장 상태가 셀렉션 목록/상세/마이 3곳에서 항상 일치한다.
5. 두 상세 화면 모두 빈 상태 문구를 갖는다.
