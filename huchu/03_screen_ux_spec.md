# 클린루프 화면 / UX 설계서

작성일: 2026-07-09  
문서 목적: 네 개 주요 페이지를 기준으로 앱 화면 구조와 핵심 사용자 흐름을 정의한다.

## 1. UX 방향

클린루프는 청소를 “관리해야 하는 목록”이 아니라 “상태를 보고 바로 해결하는 흐름”으로 보여준다. 화면은 초반 입력을 줄이고, 사용자가 앱을 처음 열어도 기본 추천 주기를 바로 확인할 수 있게 한다.

디자인 톤은 밝고 실용적이어야 한다. 청소를 못했다고 압박하기보다, 지금 할 수 있는 작은 선택지를 보여준다. 색상은 장식이 아니라 상태를 읽는 장치로 사용한다.

## 2. 하단 네비게이션

| 탭 | 이름 | 주요 목적 |
| --- | --- | --- |
| 1 | 주기 | 상태 확인, 주기 생성/수정/완료, 빠른 해결 |
| 2 | 커뮤니티 | 관리자 콘텐츠, 청소 Q&A, 잡담, 경험 공유 |
| 3 | 청소템 | 문제별 청소 도구, 가격, 후기, 판매처 확인 |
| 4 | 마이페이지 | 메뉴를 통한 청소발자국, 히스토리, 공동 가구 관리 |

## 3. 화면 1: 주기 대시보드

### 3.1 목적

사용자가 앱을 열었을 때 오늘 관리해야 할 청소 상태를 바로 이해하게 한다. 주기 생성, 수정, 완료가 이 화면에서 가능해야 한다.

### 3.2 주요 구성

1. 상단 요약
   - 오늘의 집 상태 문장
   - 가장 먼저 보면 좋은 항목 1~2개
   - 함께 쓰는 구성원 표시

2. 상태 색상 범례
   - 초록: 정상
   - 노랑: 임박
   - 코랄: 지연
   - 파랑: 예약/요청

3. 주기 카드
   - 작업명
   - 공간
   - 담당자
   - 마지막 완료일
   - 다음 권장일
   - 상태 컬러 바
   - 완료 버튼
   - 수정 버튼

4. 새 주기 만들기 버튼
   - 작업명
   - 공간
   - 반복 주기
   - 담당자
   - 저장

5. 빠른 해결 시트
   - 문제 요약
   - 짧은 가이드
   - 필요한 청소템
   - 맡길 수 있는 서비스
   - 완료 처리

### 3.3 상태별 UX

| 상태 | 카드 표현 | 추천 액션 |
| --- | --- | --- |
| 정상 | 차분한 초록 바, 남은 일수 | 보기, 수정 |
| 임박 | 노랑 바, “곧 확인” 문구 | 준비물 보기, 미루기, 완료 |
| 지연 | 코랄 바, “권장 주기 지남” 문구 | 방법 보기, 청소템 보기, 서비스 보기, 완료 |
| 예약/요청 | 파랑 바, 일정 문구 | 요청 내역 보기, 완료 |

### 3.4 핵심 흐름

```text
주기 카드 선택
-> 빠른 해결 시트
-> 가이드 확인
-> 청소템 보기 또는 서비스 보기
-> 완료
-> 청소발자국 생성
-> 다음 주기 갱신
```

뎁스가 깊어지지 않도록 상세 시트 안에서 가이드, 청소템, 서비스를 나란히 제공한다.

## 4. 화면 2: 커뮤니티

### 4.1 목적

사용자가 청소 관련 지식을 앱 안에서 얻고, 궁금한 점을 묻고 답하며, 집안일에 대한 가벼운 이야기도 나눌 수 있게 한다.

### 4.2 주요 구성

1. 검색 또는 관심 주제 칩
   - 욕실
   - 주방
   - 세탁
   - 침구
   - 쓰레기
   - 계절 관리

2. 관리자 콘텐츠
   - 짧은 문제 해결 콘텐츠
   - 초보자 체크리스트
   - 계절별 관리법
   - 예상 소요 시간
   - 필요한 청소템 표시
   - 관련 서비스 여부 표시

3. 청소 궁금증 Q&A
   - 질문 목록
   - 사진 첨부
   - 태그
   - 답변 수
   - 도움됨 또는 채택 표시

4. 잡담/생활 이야기
   - 자유 글 목록
   - 댓글 수
   - 작성자와 작성 시점

5. 사용자 경험 공유
   - 실제 해결 경험
   - 사용한 청소템 또는 서비스
   - 사진 후기

6. 콘텐츠 상세
   - 원인
   - 준비물
   - 단계별 방법
   - 주의사항
   - 관리자 콘텐츠인 경우에만 관련 청소템/서비스
   - 저장
   - 댓글 또는 답변

### 4.3 커뮤니티 탐색 흐름

```text
커뮤니티 탭
-> 관리자 콘텐츠, 청소 궁금증, 잡담 중 선택
-> 글 목록 탐색
-> 상세 확인
-> 저장, 댓글, 답변, 도움됨 중 선택
```

관리자 콘텐츠는 필요할 때 청소템이나 청소서비스로 이어질 수 있다. 청소 궁금증 Q&A와 잡담 글에는 주기 추가, 상품/서비스 연결 흐름을 기본으로 붙이지 않는다.

## 5. 화면 3: 청소템

### 5.1 목적

이미 필요한 청소 도구를 알고 있거나, 특정 청소 문제에 맞는 도구를 고르고 싶은 사용자가 빠르게 판단하게 한다. 청소템은 직접 판매 화면이 아니라 상품 정보, 실제 후기, 판매처 옵션을 비교하는 탐색 화면이다. 장바구니와 주문을 기대하게 만들지 않되, 외부 판매처로 이동할 수 있다는 점은 명확히 보여준다.

### 5.2 주요 구성

1. 문제별 바로 해결 묶음
   - 욕실 물때
   - 배수구 냄새
   - 세탁조 냄새
   - 침구 관리
   - 묶음별 대표 상품과 후기 요약

2. 청소 도구/소모품
   - 세제
   - 솔/천/장갑
   - 소모품
   - 관리 키트
   - 상품 이미지
   - 브랜드
   - 가격
   - 할인율
   - 평점과 후기 수

3. 상품 상세
   - 이미지 갤러리
   - 브랜드와 상품명
   - 정가, 판매가, 할인율
   - 핵심 용도
   - 사용자 후기
   - 후기 사진
   - 청소 문제별 만족도

4. 판매처 옵션
   - 판매처명
   - 가격
   - 배송비 또는 배송 조건
   - 가격 확인 시점
   - 최저가 후보 표시
   - 외부 판매처 이동

5. 찜과 선택적 해결 기록
   - 청소템 찜
   - 외부 판매처 이동
   - 주기 화면에서 진입한 경우에만 원래 주기 상세로 돌아가기
   - 독립적으로 청소템을 탐색한 경우에는 주기 선택을 요구하지 않음

### 5.3 청소템 카드 원칙

- 상품 이미지를 충분히 크게 보여준다.
- 브랜드, 가격, 할인율, 평점, 후기 수를 카드에서 바로 확인할 수 있게 한다.
- 왜 필요한지 먼저 설명한다.
- 판매처 가격은 참고 정보로 보여주고, 실시간 최저가를 보장하는 것처럼 표현하지 않는다.
- 사용자 후기를 상품 선택의 핵심 정보로 둔다.
- 과장된 문구보다 사용 상황을 보여준다.
- 주기 연결은 필수가 아니라 주기 화면에서 진입한 경우의 보조 흐름으로 둔다.

## 6. 화면 4: 마이페이지

### 6.1 목적

사용자의 청소 기록과 공동 사용 상태를 메뉴별로 확인하게 한다. 마이페이지 첫 화면은 모든 정보를 펼쳐놓기보다 각 항목으로 들어가는 메뉴 허브 역할을 한다.

### 6.2 주요 구성

1. 프로필/가구 요약
   - 사용자 이름
   - 현재 가구 이름
   - 구성원 수

2. 메뉴 목록
   - 청소발자국
   - 완료 히스토리
   - 공동 가구
   - 담당 현황
   - 이번 주 요약
   - 내 커뮤니티 활동
   - 찜한 청소템
   - 알림/설정

3. 청소발자국 메뉴
   - 최근 완료 기록
   - 직접 완료, 청소템 확인 후 완료, 서비스 요청 후 완료 구분
   - 담당자 표시

4. 완료 히스토리 메뉴
   - 기간별 완료 기록
   - 완료 방식별 필터

5. 공동 가구 메뉴
   - 구성원 목록
   - 초대 버튼

6. 담당 현황 메뉴
   - 구성원별 담당 중인 작업
   - 담당자 변경 진입점

7. 이번 주 요약 메뉴
   - 완료 수
   - 지연 해결 수
   - 함께 완료한 작업

8. 내 커뮤니티 활동 메뉴
   - 내가 쓴 질문
   - 내가 쓴 답변
   - 댓글 단 글

9. 찜한 청소템 메뉴
   - 저장한 상품
   - 최근 확인한 판매처
   - 외부 이동 이력

## 7. 온보딩 설계

온보딩은 기본 추천 주기 확인과 공동 사용 여부 선택만 남긴다.

```text
1. 서비스 가치 한 문장
2. 기본 추천 주기 확인
3. 함께 쓰는 사람 여부 선택
4. 주기 대시보드 진입
```

사용자는 언제든 건너뛸 수 있어야 하며, 대시보드는 기본 추천 항목으로 채워져 있어야 한다.

## 8. 핵심 플로우

### 8.1 첫 완료 플로우

```text
앱 실행
-> 주기 대시보드
-> 지연 카드 확인
-> 빠른 해결 시트
-> 가이드 확인
-> 완료
-> 청소발자국 생성
```

### 8.2 주기 생성 플로우

```text
주기 탭
-> 새 주기
-> 작업명, 공간, 반복 주기, 담당자 입력
-> 저장
-> 대시보드 카드 생성
```

### 8.3 관리자 콘텐츠에서 청소템으로 이어지는 플로우

```text
커뮤니티 탭
-> 관리자 콘텐츠
-> 욕실 물때 콘텐츠
-> 준비물 확인
-> 물때 제거 청소템 보기
-> 청소템 상품 상세
-> 후기 확인
-> 판매처 확인
-> 외부 판매처 이동
```

### 8.4 커뮤니티 Q&A 플로우

```text
커뮤니티 탭
-> 청소 궁금증
-> 질문 작성
-> 답변/댓글 확인
-> 도움됨 표시
```

### 8.5 관리자 콘텐츠에서 서비스로 이어지는 플로우

```text
커뮤니티 탭
-> 관리자 콘텐츠
-> 에어컨 냄새 콘텐츠
-> 직접 가능한 범위 확인
-> 전문 서비스 보기
-> 서비스 카드 확인
-> 외부 서비스 요청 이동
```

### 8.6 공동 사용 플로우

```text
마이페이지
-> 공동 가구 메뉴
-> 구성원 초대
-> 주기 카드에서 담당자 지정
-> 완료 기록이 담당자 이름으로 저장
```

## 10. 문구 톤

| 상황 | 권장 문구 |
| --- | --- |
| 지연 | “권장 주기를 조금 넘겼어요. 오늘 가능한 방법부터 볼까요?” |
| 임박 | “이번 주 안에 확인하면 다음 청소가 쉬워져요.” |
| 완료 | “완료했어요. 다음 점검일을 잡아둘게요.” |
| 청소템 연결 | “이 문제에 필요한 준비물이에요.” |
| 서비스 연결 | “직접 하기 번거롭다면 맡길 수도 있어요.” |
| 공동 사용 | “이번 담당자는 민지님이에요.” |

## 11. HTML 프로토타입 반영 기준

프로토타입은 단일 HTML 파일로 구현한다.

- 모바일 앱 프레임을 기준으로 만든다.
- 하단 네비게이션 4개 탭을 모두 구현한다.
- 주기 생성, 수정, 완료가 동작해야 한다.
- 주기 상태는 색상으로 구분한다.
- 커뮤니티에는 관리자 콘텐츠, 청소 Q&A, 잡담 영역이 보여야 한다.
- 관리자 콘텐츠에서만 맥락에 맞는 청소템/서비스 연결이 보여야 한다.
- 청소템은 상품 이미지, 브랜드, 가격, 할인율, 후기, 판매처 중심으로 구성한다.
- 마이페이지는 메뉴 목록을 먼저 보여주고, 각 항목은 메뉴 진입 후 상세가 나타나야 한다.
- 사용자가 초반에 많은 입력을 하지 않아도 기본 상태를 확인할 수 있어야 한다.
