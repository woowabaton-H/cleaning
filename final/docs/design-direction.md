이 문서는 `final-plan.md`의 제품 방향은 유지하되, 현재 프로토타입의 화면 톤, 문구, 카드 구조, 마이 페이지 정보구조를 다시 잡기 위한 기준 문서다.

참고한 자료:

- `final/docs/source-analysis.md`
- `final/prototype/index.html`
- `final/prototype/app.js`

기존 요구사항과 이 문서가 충돌할 경우, 다음 프로토타입 디자인에는 이 문서를 우선 적용한다. 특히 셀렉션 카드, 마이 페이지의 기록 노출 방식, 주기 카드의 시각적 상태 표현은 이 문서 기준으로 재정의한다.

## 2. 디자인 목표

클린루프는 청소를 완벽하게 시키는 앱이 아니라, 사용자가 생활 속에서 다시 챙길 수 있게 도와주는 앱이다. 디자인은 깨끗하고 가볍고 친근해야 한다.

핵심 방향:

- 하얀 배경을 기본으로 둔다.
- 청소와 잘 어울리는 맑은 파란색을 브랜드 중심 색으로 사용한다.
- 카테고리마다 아기자기하고 귀여운 아이콘을 둔다.
- 문구는 사용자를 다그치지 않고, 대신 기억해주는 느낌을 준다.
- 주기 카드는 일정 상태가 눈에 바로 들어오도록 색상과 레이아웃을 강하게 구분한다.
- 셀렉션은 하나의 카드가 하나의 서비스 또는 하나의 상품을 대표한다.
- 마이 페이지는 요약과 메뉴 중심으로 정리하고, 상세 기록은 별도 화면에서 본다.

## 3. 현재 final 프로토타입의 문제

| 영역 | 현재 문제 | 변경 방향 |

| 문구 | `완료`, `주기 수정`, `큰 카테고리 단위로만 관리합니다`처럼 기능 설명이 딱딱하다. | `했어요`, `주기 바꾸기`, `다음은 제가 기억할게요`처럼 행동과 감정이 부드럽게 연결되게 쓴다. |
| 홈 주기 카드 | 모든 카드가 비슷한 흰 카드라 긴급도와 일정 상태가 잘 보이지 않는다. | 일정 상태별 배경색, 아이콘, 상태 배지를 크게 다르게 둔다. |
| 홈 기록 영역 | `이번 달 기록`이 홈 하단에 바로 노출되어 홈의 핵심인 오늘/이번 주 관리 흐름을 분산시킨다. | 홈에서는 주기와 오늘 할 일에 집중하고, 완료 히스토리는 마이의 별도 메뉴로 이동한다. |
| 셀렉션 카드 | `침구 수거 서비스 비교`, `문앞 수거 서비스 3곳`처럼 한 카드 안에 여러 후보가 묶여 있다. | 서비스나 상품 하나가 카드 하나가 되게 분리한다. |
| 셀렉션 정보 | 추천 이유가 크게 보이고, 가격/후기/업체 신뢰 정보가 상대적으로 약하다. | 가격, 평점, 후기 수, 제공처, 제휴 여부를 카드의 핵심 정보로 올린다. |
| 마이 페이지 | 최근 완료와 저장 셀렉션이 같은 화면에 길게 붙어 있다. | 마이 첫 화면은 프로필, 요약, 메뉴로 정리하고 `완료 히스토리`, `저장한 셀렉션`은 별도 화면으로 분리한다. |
| 아이콘 | 선형 SVG 중심이라 귀엽고 생활감 있는 인상이 약하다. | 카테고리별 파스텔 아이콘 타일 또는 작은 일러스트 스티커를 사용한다. |

## 4. 브랜드 톤

### 4.1 성격

클린루프의 말투는 `다정한 생활 메이트`에 가깝다. 사용자를 가르치거나 평가하지 않고, 해야 할 일을 대신 기억해주고 작게 시작하도록 돕는다.

브랜드 키워드:

- 깨끗한
- 가벼운
- 다정한
- 똑똑하지만 티 내지 않는
- 생활감 있는
- 다시 시작하기 쉬운

피해야 할 톤:

- 지시형: `해야 합니다`, `반드시`, `관리해야 해요`
- 평가형: `미뤘어요`, `놓쳤어요`, `부족해요`
- 설명 과잉형: 한 화면에서 서비스 철학을 길게 설명하는 문장
- 구매 유도형: 추천보다 판매가 먼저 보이는 문장

### 4.2 문구 원칙

1. 사용자가 못한 일을 지적하지 않는다.
2. 다음 행동을 하나만 제안한다.
3. 긴 설명보다 짧은 안심 문장을 먼저 둔다.
4. 완료 후에는 칭찬보다 다음을 기억해준다는 메시지를 준다.
5. 가격, 후기, 제휴 여부는 숨기지 않고 담백하게 표시한다.

문장 길이 기준:

- 제목: 12~20자 권장
- 보조 문구: 1~2문장, 총 45자 이내 권장
- 버튼: 2~7자 권장
- 토스트: 제목 12자 이내, 설명 35자 이내 권장

### 4.3 문구 교체 예시

| 현재 | 변경안 |
| --- | --- |
| 오늘 청소부터 챙겨요. | 오늘은 여기만 챙겨도 충분해요 |
| 큰 카테고리만으로 시작해요. 했으면 완료하고, 주기가 안 맞으면 바로 바꾸면 됩니다. | 다 한 일은 `했어요`만 눌러주세요. 다음 주기는 제가 기억할게요. |
| 완료 | 했어요 |
| 주기 수정 | 주기 바꾸기 |
| 도움 보기 | 도움 볼래요 |
| 이번 주에 챙기면 좋아요 | 오늘 살짝 챙겨볼까요? |
| N일 뒤 다시 보면 충분해요 | 아직 여유 있어요 · D-N |
| 셀렉션을 저장했어요. | 담아뒀어요. 필요할 때 다시 볼 수 있어요. |
| 저장을 해제했어요. | 담아둔 목록에서 뺐어요. |
| 외부 페이지 연결 CTA 예시입니다. | 가격과 예약 가능 여부를 확인해볼게요. |
| 카테고리를 추가했어요. | 새 주기도 제가 기억해둘게요. |
| 압박이 아니라 기억 보조로만 알려드려요. | 꼭 필요할 때만 조용히 알려드릴게요. |

## 5. 비주얼 방향

### 5.1 전체 배경과 면 구성

기본 화면은 흰색을 유지한다. 카드와 화면 배경을 모두 회색으로 분리하기보다, 흰 바탕 위에 아주 연한 파란색 또는 파스텔 상태색으로 필요한 곳만 강조한다.

권장 구조:

- 앱 배경: `#FFFFFF`
- 보조 배경: `#F6FAFF`
- 카드 배경: `#FFFFFF`
- 구분선: `#E7EEF7`
- 주요 CTA: 맑은 파란색
- 상태 카드: 파스텔 배경과 선명한 상태 배지

현재 프로토타입의 초록/청록 중심 팔레트는 줄인다. 초록은 `완료`, `안정`, `청결함` 상태에만 제한적으로 사용한다.

### 5.3 타이포그래피

권장 폰트:

- iOS/웹 기본: `Pretendard`, `Apple SD Gothic Neo`, `-apple-system`, `BlinkMacSystemFont`, `sans-serif`
- 제목은 단단하게, 본문은 넉넉한 행간을 준다.
- 모바일 카드 내부에서는 제목 15~17px, 보조 문구 12~14px를 기준으로 한다.
- 버튼 문구는 13~15px, 800 이상 두께를 사용한다.

주의:

- 화면 안쪽 카드에서 hero급 대형 타이틀을 남발하지 않는다.
- 자간은 0으로 둔다.
- 긴 문구가 버튼 안에 들어가지 않게 한다.

### 5.4 아이콘 방향

아이콘은 선형 SVG만 쓰지 않는다. 카테고리별로 작은 스티커처럼 보이는 아이콘 타일을 사용한다. 첨부된 카테고리 화면처럼 한눈에 카테고리를 알아볼 수 있어야 한다.

권장 스타일:

- 44~56px 정사각형 또는 원형 타일
- 파스텔 배경
- 안쪽 아이콘은 단순하고 둥근 형태
- 필요하면 이모지 기반 프로토타입으로 시작하고, 이후 커스텀 PNG/SVG로 교체한다.

카테고리별 아이콘 방향:

| 카테고리 | 아이콘 방향 | 배경 |
| --- | --- | --- |
| 욕실 | 물방울, 샤워기, 스퀴지 | 연파랑 |
| 주방 | 수세미, 프라이팬, 싱크대 | 연노랑 |
| 세탁/침구 | 빨래바구니, 이불, 세탁기 | 연보라/연파랑 |
| 쓰레기/수거 | 작은 봉투, 재활용 박스 | 연민트 |
| 바닥/먼지 | 빗자루, 롤클리너 | 연초록 |
| 계절/가전 | 에어컨, 선풍기, 필터 | 연하늘 |
| 반려동물 | 발바닥, 돌돌이, 패드 | 연핑크 |

## 6. 홈 디자인

### 6.1 홈의 역할

홈은 기록을 보여주는 화면이 아니라, 오늘 또는 이번 주에 챙기면 좋은 청소 리듬을 보여주는 화면이다. 사용자가 앱을 열었을 때 바로 알아야 하는 것은 `무엇을 하면 되는지`, `얼마나 급한지`, `끝나면 어디를 누르면 되는지`다.

홈 상단 구조:

1. 인사와 날짜
2. 오늘의 한 줄 제안
3. 이번 주 진행 요약
4. 주기 카드 목록

권장 문구:

- `보송님, 오늘은 여기만 봐도 충분해요`
- `급한 것부터 위에 올려뒀어요`
- `다 하면 다음 주기는 제가 기억할게요`

### 6.2 주기 카드 구조

주기 카드는 현재보다 훨씬 더 눈에 띄어야 한다. 몽이 프로토타입처럼 일정 상태별 색상이 카드 전체에 반영되어야 한다.

카드 기본 구성:

```text
[아이콘 타일]  욕실
              오늘 살짝 챙겨볼까요?
              마지막 7월 1일 · 14일 주기

[상태 배지] D+2
[했어요] [도움 볼래요]
```

카드 규칙:

- 카드 전체를 탭하면 상세 또는 해결 흐름으로 들어간다.
- `했어요`는 가장 빠르게 누를 수 있어야 한다.
- `주기 바꾸기`는 카드 안의 3번째 동일 버튼이 아니라 상세 또는 더보기에서 제공한다.
- 긴 설명 문구는 카드에서 줄이고, 상세에서 보여준다.
- 급한 카드가 위에 오도록 정렬한다.

### 6.3 주기 상태 컬러

| 상태 | 조건 | 카드 색 | 배지 문구 | 사용자 느낌 |
| --- | --- | --- | --- | --- |
| `late` | 다음 관리일이 지남 | `soft-pink` | `살짝 밀렸어요` | 가장 먼저 눈에 들어와야 함 |
| `due` | 오늘 또는 이번 주 안에 권장 | `clean-blue-soft` | `오늘 좋아요` | 지금 하면 좋음 |
| `soon` | 1~2일 남음 | `soft-yellow` | `곧 챙겨요` | 곧 돌아옴 |
| `good` | 3일 이상 남음 | 흰 카드 + 파란 아이콘 | `아직 여유` | 안정적 |
| `doneToday` | 오늘 완료 | `fresh-mint` | `오늘 반짝` | 완료 피드백 |

색상만으로 상태를 전달하지 않는다. 배지와 문구가 함께 있어야 한다.

### 6.4 홈에서 제거하거나 축소할 것

- `이번 달 기록` 가로 카드 목록은 홈에서 제거한다.
- 완료 수 원형 미터는 작게 유지하거나, 이번 주 진행 요약으로 바꾼다.
- 카테고리 설명이 카드마다 길게 반복되는 구조를 줄인다.

## 7. 셀렉션 디자인

### 7.1 셀렉션의 역할

셀렉션은 브랜드가 고른 상품과 서비스를 보여주는 공간이다. 다만 사용자는 `왜 골랐는지`보다 먼저 `얼마인지`, `후기가 어떤지`, `어떤 상황에 맞는지`, `제휴인지`를 알고 싶어 한다.

따라서 카드의 우선순위는 다음과 같다.

1. 상품/서비스명
2. 가격 또는 가격대
3. 평점과 후기 수
4. 카테고리와 타입
5. 간단한 적합 상황
6. 제휴 여부

`고른 이유`는 카드 필수 정보에서 제외한다. 필요하다면 상세 화면에서 `확인하면 좋은 점` 또는 `추천 메모` 정도로 낮은 우선순위에 둔다.

### 7.2 카드 하나의 기준

하나의 셀렉션 카드는 하나의 상품 또는 하나의 서비스만 대표한다.

현재 구조에서 바꿀 예:

| 현재 카드 | 변경 |
| --- | --- |
| 침구 수거 서비스 비교 | `런드리고 침구 수거`, `세탁특공대 야간 수거`, `동네 세탁소 찾기`로 분리 |
| 문앞 수거 서비스 3곳 | `오늘수거 정기 수거`, `커버링 주 1회 수거`, `로컬 수거팀 맞춤 수거`로 분리 |
| 에어컨 필터와 분해청소 기준 | `에어컨 필터 직접 세척`, `미소 에어컨 청소`, `제조사 공식 케어`로 분리 |

### 7.3 셀렉션 카드 구조

```text
[아이콘/상품 썸네일]  곰팡이 제거 젤 250g
                    욕실 · 용품
                    6,900원부터
                    ★ 4.8 · 후기 1,240
                    타일 줄눈에 바르고 기다리는 젤 타입

[제휴] [내일 도착] [초보 쉬움]
[담아두기] [가격 보기]
```

서비스 카드 예:

```text
[서비스 아이콘]  오늘수거 정기 수거
               쓰레기/수거 · 서비스
               월 9,900원부터
               ★ 4.9 · 후기 3,105
               주 1~2회 문앞 수거

[제휴] [정기] [지역 확인 필요]
[담아두기] [예약 가능 보기]
```

### 7.4 상세 화면

상세는 판매 페이지처럼 만들지 않는다. 사용자가 확인해야 하는 정보를 정리한다.

상세 구성:

1. 가격과 후기 요약
2. 이런 상황에 맞아요
3. 사용 전 확인할 점
4. 제휴/가격 변동 고지
5. 외부 보기 CTA

권장 문구:

- `가격과 후기는 바뀔 수 있어요. 이동 전 한 번 더 확인해 주세요.`
- `클린루프는 선택을 돕고, 결제와 예약은 외부에서 진행돼요.`
- `제휴 상품은 표시해둘게요. 추천 순서는 제휴 여부만으로 정하지 않아요.`

## 8. 커뮤니티 디자인

커뮤니티는 이번 요청의 핵심 변경 범위는 아니지만, 톤은 홈과 셀렉션에 맞춰 정리한다.

방향:

- `꿀팁 공유`, `Q&A`라는 구조는 유지한다.
- 제목은 사용자가 겪는 문제를 바로 말하게 한다.
- 카드에는 카테고리 아이콘, 난이도, 걸리는 시간을 함께 표시한다.
- 위험 정보가 있는 글에는 안전 배지를 둔다.
- 글 상세에서는 상품 연결보다 해결 방법과 안전 안내를 먼저 둔다.

문구 예:

- `욕실 물때, 세제보다 물기 제거가 먼저예요`
- `수건 냄새가 남을 때는 세탁조부터 봐요`
- `직접 해도 되고, 맡겨도 괜찮아요`

## 9. 마이 페이지 디자인

### 9.1 마이의 역할

마이 페이지는 모든 기록을 한 화면에 펼치는 곳이 아니다. 사용자의 청소 리듬을 요약하고, 필요한 상세 메뉴로 들어가는 허브다.

마이 첫 화면 구성:

1. 프로필 요약
2. 청소발자국 요약
3. 최근 12주 시각화
4. 메뉴 목록

메뉴:

- 완료 히스토리
- 저장한 셀렉션
- 주기 관리
- 알림 설정
- 내 정보

### 9.2 마이 첫 화면에서 분리할 것

다음 목록은 마이 첫 화면에 직접 펼치지 않는다.

- 최근 완료 전체 목록
- 저장한 셀렉션 카드 목록

대신 메뉴 행으로 제공한다.

```text
완료 히스토리       이번 달 8개 >
저장한 셀렉션       3개 담아둠 >
주기 관리           6개 사용 중 >
알림 설정           조용히 알려드림 >
```

### 9.3 완료 히스토리 화면

별도 화면 또는 전체 바텀시트로 제공한다.

구성:

- 월별 필터
- 카테고리 필터
- 완료 기록 리스트
- 직접 해결 / 맡겨서 해결 구분
- 빈 상태 문구

빈 상태 문구:

- `아직 기록이 없어요`
- `처음 한 일을 남기면 다음 주기는 제가 기억할게요`

### 9.4 저장한 셀렉션 화면

별도 화면 또는 전체 바텀시트로 제공한다. 셀렉션 탭과 같은 카드 구조를 재사용하되, 저장 해제 액션을 명확히 둔다.

빈 상태 문구:

- `담아둔 셀렉션이 없어요`
- `괜찮아 보이는 상품이나 서비스를 담아두면 여기서 다시 볼 수 있어요`

## 10. 주요 컴포넌트 기준

### 10.1 카테고리 아이콘 타일

- 크기: 48px 기본
- 반경: 16px
- 배경: 카테고리별 파스텔
- 안쪽 아이콘: 26~30px
- 카드 내부에서 이름보다 먼저 시선이 가게 배치한다.

### 10.2 주기 카드

- 최소 높이: 112px
- 반경: 16px
- 상태별 배경 사용
- 왼쪽 상단 아이콘, 중앙 제목/문구, 오른쪽 상단 상태 배지
- 하단에는 `했어요` 버튼과 보조 액션 1개만 둔다.

### 10.3 셀렉션 카드

- 하나의 카드에 하나의 상품/서비스
- 썸네일 또는 아이콘 영역 필수
- 가격은 제목 다음으로 강하게 표시
- 평점/후기 수 필수
- 제휴 여부 태그 필수
- 추천 이유 블록은 카드에서 제거

### 10.4 메뉴 행

- 마이 페이지의 주요 상세 진입은 카드형 목록보다 메뉴 행을 우선한다.
- 오른쪽에 요약 값과 화살표를 둔다.
- 한 행 높이 56~64px
- 행 전체가 탭 가능해야 한다.

### 10.5 토스트

현재 토스트는 한 줄 텍스트라 정보가 차갑게 느껴진다. 몽이 프로토타입처럼 아이콘, 제목, 설명을 분리한다.

예:

```text
✨ 반짝반짝해졌어요
다음 주기는 제가 기억할게요
```

## 11. 기능 요구사항 수정 메모

다음 요구사항은 다음 문서 업데이트 때 수정이 필요하다.

| 요구사항 | 수정 방향 |
| --- | --- |
| `HM-04` 홈의 이번 달 기록 노출 | 홈에서 제거하거나 요약 링크로 축소한다. 실제 목록은 마이 `완료 히스토리`로 이동한다. |
| `SL-07` 셀렉션 카드의 추천 이유 표시 | 카드 필수 정보에서 제외하고, 가격/후기/서비스명 중심으로 바꾼다. |
| `SL-09`, `SL-10` 제공업체 후보 표시 | 한 카드 안 provider list가 아니라 업체별 독립 셀렉션 카드로 분리한다. |
| `SL-13` 상세의 `고른 이유` | `확인하면 좋은 점` 또는 `추천 메모`로 낮은 우선순위에 둔다. |
| `MY-05` 최근 완료 기록 표시 | 마이 첫 화면이 아니라 `완료 히스토리` 메뉴 안에서 표시한다. |
| `MY-09` 저장한 셀렉션 목록 표시 | 마이 첫 화면이 아니라 `저장한 셀렉션` 메뉴 안에서 표시한다. |

## 12. 다음 프로토타입 작업 순서

1. 색상 토큰을 파란색 중심으로 재정의한다.
2. 카테고리 아이콘 타일을 만든다.
3. 홈 주기 카드를 상태별 컬러 카드로 다시 만든다.
4. 홈에서 `이번 달 기록` 목록을 제거한다.
5. 셀렉션 데이터를 상품/서비스 단위로 쪼갠다.
6. 셀렉션 카드에서 가격, 평점, 후기 수를 핵심 정보로 올린다.
7. 마이 페이지를 요약 + 메뉴 구조로 바꾼다.
8. `완료 히스토리`와 `저장한 셀렉션` 상세 화면을 추가한다.
9. 버튼, 토스트, 바텀시트 문구를 브랜드 톤에 맞게 교체한다.
10. 모바일 360px~430px 폭에서 텍스트 넘침과 카드 가독성을 확인한다.

## 13. 프로토타입 검수 기준

다음 조건을 만족해야 다음 디자인 시안으로 인정한다.

- 첫 화면을 봤을 때 흰 배경과 파란 브랜드 톤이 즉시 느껴진다.
- 주기 카드 중 급한 항목이 1초 안에 눈에 들어온다.
- 각 카테고리 아이콘만 봐도 어떤 청소 영역인지 이해된다.
- 셀렉션 카드 하나가 하나의 상품 또는 서비스만 나타낸다.
- 셀렉션 카드에서 가격과 후기를 바로 확인할 수 있다.
- 마이 첫 화면에 최근 완료 목록과 저장 셀렉션 목록이 길게 펼쳐져 있지 않다.
- 버튼 문구가 딱딱한 명령형이 아니라 사용자의 행동 언어에 가깝다.
- 제휴, 가격 변동, 외부 예약/구매 고지가 숨겨져 있지 않다.
