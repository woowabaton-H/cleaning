# 원본 산출물 분석 및 최종 채택 기준

작성일: 2026-07-10  
대상 폴더: `huchu`, `if`, `몽이`, `테리`  
최종 방향: 서비스명은 미정이며, 문서와 프로토타입에서는 가칭 `클린루프`로 표기한다.

## 1. 분석 관점

네 사람의 산출물을 단순히 섞지 않고, 다음 질문으로 다시 보았다.

1. 사용자가 실제로 겪는 청소 문제를 가장 잘 설명하는가?
2. MVP에서 반복 사용을 만들 핵심 행동이 분명한가?
3. 청소 서비스 도메인에서 운영 가능한 범위인가?
4. 커머스, 서비스 연결, 커뮤니티가 제품 신뢰를 해치지 않는가?
5. 프로토타입에서 하나의 제품 경험으로 이어질 수 있는가?

이번 수정의 결론은 명확하다. MVP의 중심은 구매나 예약이 아니라 `큰 카테고리 기반 청소 주기 관리`다. 사용자는 홈에서 오늘 또는 이번 주에 관리할 카테고리를 보고, 완료하고, 주기를 조정할 수 있어야 한다. 막히는 문제는 브랜드 셀렉션과 커뮤니티를 통해 해결한다.

## 2. 원본별 핵심 분석

### 2.1 huchu

| 항목 | 분석 |
| --- | --- |
| 핵심 문제 정의 | 청소 주기가 보이지 않으면 밀리고, 청소 지식과 실행 수단이 검색/쇼핑/서비스 앱으로 흩어진다는 문제를 잘 잡았다. |
| 타깃 사용자 | 바쁜 1인 가구와 자취 초보 사용자가 최종 MVP와 잘 맞는다. 원본의 공동 생활 관점은 이번 MVP에서는 제외한다. |
| 서비스 콘셉트 | 주기 관리, 커뮤니티, 청소템 탐색을 나눠두되 필요한 순간에 이어주는 구조가 좋다. |
| 주요 기능 | 주기 대시보드, 상태 색상, 완료 기록, 커뮤니티, 청소템 상세, 마이페이지가 정리되어 있다. |
| 사용자 여정 | 홈에서 상태를 보고 해결 정보로 이동한 뒤 완료 기록으로 돌아오는 반복 루프가 선명하다. |
| 운영 관점의 장점 | 직접 판매, 장바구니, 주문/배송을 MVP 밖으로 둔 판단이 현실적이다. |
| UX/UI 장점 | 복잡한 예약보다 주기와 도움 보기 중심으로 접근하기 쉽다. |
| 부족하거나 애매한 점 | 공동 가구, 관리자 콘텐츠, 세부 청소 항목이 함께 들어가면 MVP 초점이 흐려질 수 있다. |
| 최종 채택 | 개인 사용자 중심의 주기 관리 구조, 커뮤니티와 청소템 분리 원칙, 직접 판매 제외 판단을 채택한다. |

### 2.2 if

| 타깃 사용자 | 자취 1~3년차, 바쁜 직장인, 청소 초보 사용자는 최종 MVP와 맞는다. 룸메이트/공동가구와 B2B 확장 타깃은 제외한다. |

| 주요 기능 | 홈 상태 카드, 해결 플로우, 주기 보드, 용품 연결, 서비스 연결, 알림, 완료 기록. |
| 예약/견적/매칭/결제 | 업체 카드와 가격/제공 범위 정의는 실무적이지만, 이번 MVP에서는 외부 서비스 후보 소개 수준으로 축소한다. |
| 운영 관점의 장점 | 자체 구독 크레딧과 직접 운영을 초기 범위에서 제외하고 제휴/중개부터 검증하는 판단이 좋다. |

| 부족하거나 애매한 점 | 문제 해결 플로우가 강해지면 사용자의 주기 관리보다 구매/예약이 앞서 보일 수 있다. |
| 최종 채택 | 제휴/중개형 운영 범위, 추천 근거와 제휴 표시, 정적 HTML/CSS/JS 기반 구현 구조를 채택한다. |

| 부족하거나 애매한 점 | 서비스 예약과 커머스가 강해지면 MVP의 핵심인 주기 관리보다 외부 전환이 앞설 수 있다. |
| 최종 채택 | 홈 중심 주기 관리, 청소발자국, 부드러운 알림, 카테고리 완료 경험을 채택한다. |

| 주요 기능 | 주기 대시보드, 커뮤니티/가이드, 커머스 가격 비교, 업체 연결, 청소발자국. |

| 부족하거나 애매한 점 | 가격/업체/예약 정보가 구체적인 만큼 MVP에서 모두 담으면 서비스 범위가 과도해질 수 있다. |
| 최종 채택 | 브랜드 신뢰 원칙, 추천 이유 공개, 안전/제휴 투명성, 서비스명 가칭 처리 원칙을 채택한다. |

## 3. 반복되는 공통 방향성

1. 사용자는 청소를 몰라서가 아니라 기억, 판단, 실행이 끊겨서 미룬다.
2. 첫 사용에서 많은 입력을 요구하면 실패한다.
3. 기본 카테고리와 추천 주기가 먼저 있어야 한다.
4. 완료 기록은 제품의 핵심 데이터다.
5. 청소 정보, 용품, 서비스는 흩어져 있으며 사용자는 믿을 만한 선별을 원한다.
6. 추천은 광고처럼 보이면 안 된다. 추천 이유와 제휴 여부가 필요하다.
7. 직접 판매, 자체 물류, 자체 인력 운영은 초기 MVP에 부담이 크다.

## 4. 최종안에 반영한 강점

| 채택 요소 | 출처 | 최종 반영 방식 |
| --- | --- | --- |
| 큰 카테고리 기반 주기 관리 | huchu, 몽이, 테리 | 홈에서 욕실, 주방, 세탁/침구, 쓰레기/수거, 바닥/먼지, 계절/가전을 관리 |
| 홈과 주기 흐름 통합 | 몽이 | 하단 탭에서 별도 주기 탭을 없애고 홈이 곧 주기 관리 화면이 되게 구성 |
| 완료 기록 중심 | huchu, if, 몽이 | 완료 버튼을 핵심 CTA로 두고 다음 관리일을 자동 갱신 |
| 직접 판매 제외 | huchu, if | 셀렉션은 외부 연결과 저장 중심으로 두고 장바구니/결제/배송은 제외 |
| 브랜드가 고른 이유 공개 | if, 테리 | 셀렉션 카드에 추천 이유, 맞는 상황, 가격대, 제휴 여부를 함께 표시 |
| 부드러운 알림과 재시작 톤 | 몽이, 테리 | 지연 카드 대신 이번 주 관리 제안과 가벼운 리마인드로 표현 |
| 커뮤니티의 문제 해결성 | huchu, 테리 | 관리자 가이드와 잡담을 제거하고 꿀팁 공유/Q&A로 단순화 |
| 청소발자국 | 몽이 | 마이에서 완료 기록과 최근 12주 활동을 보여줌 |

| 아이디어 | 출처 | 판단 |

| 홈에서 루프를 바로 느끼게 하는 모바일 프로토타입 감각 | 몽이 | 최종 프로토타입의 홈 구조와 완료 인터랙션에 강하게 반영 |

## 6. 충돌한 방향성과 최종 판단

| 충돌 지점 | 원본 방향 | 최종 판단 |
| --- | --- | --- |
| 서비스명 | `클린루프`, `보송 매니저` 등으로 나뉨 | 이름은 확정하지 않는다. 현재는 가칭 `클린루프`로만 표기한다. |
| 핵심 시나리오 | 직접 해결, 용품 구매, 외주 예약 흐름이 강한 원본이 있음 | MVP 핵심 시나리오는 주기 확인, 완료, 주기 수정이다. |
| 탭 구조 | 홈/주기/해결/커뮤니티/마이 등으로 분리 | 홈과 주기는 통합하고, 해결은 브랜드 `셀렉션`으로 재정의한다. |
| 청소 항목 수준 | 세부 이슈 프리셋과 상세 작업이 많음 | MVP 주기 관리는 큰 카테고리만 다룬다. 세부 항목은 콘텐츠 맥락에서만 다룬다. |
| 커뮤니티 구조 | 관리자 가이드, Q&A, 잡담, 경험 공유 등 다양함 | 꿀팁 공유와 Q&A만 둔다. 반응 좋은 글은 상단에 강조한다. |
| 공동 가구 | 일부 원본에서 담당자/공유 기능 제안 | 개인 사용자 MVP에서는 제외한다. |
| B2B | 숙박/임대/오피스 관리 확장 제안 | 이번 MVP 페르소나와 기능 범위에서 제외한다. |
| 지연 카드 | 여러 원본에서 지연/방치 상태 강조 | 압박감이 커지므로 제거하고, 이번 주 관리 제안으로 바꾼다. |
| 예약/결제 | 일부 원본에서 업체 매칭과 예약 확인까지 제안 | MVP에서는 서비스 후보 소개와 외부 연결 가능성까지만 둔다. |

## 7. 최종안에서 버린 요소

1. 세부 청소 항목별 주기 관리.
2. 지연 카드, 연체, 방치 중심 표현.
3. 공동 가구 초대, 담당자 배정, 공유 기록.
4. 개인 숙박 운영자, 원룸/오피스텔 관리자, 소규모 오피스 관리자 페르소나.
5. 관리자 가이드 탭.
6. 커뮤니티 잡담 탭.
7. 자체 결제, 장바구니, 배송, 환불.
8. 업체 실시간 예약 API와 즉시 매칭.
9. 자체 청소 인력 운영.
10. 자체 크레딧 구독.
11. 사진 기반 AI 진단.

## 8. 새롭게 보완한 빈틈

| 빈틈 | 보완 |
| --- | --- |
| 주기 관리가 복잡해질 위험 | 큰 카테고리만 등록하고 완료/주기 수정만 제공 |
| 용품/서비스가 광고처럼 보일 위험 | 셀렉션을 편집숍 톤으로 바꾸고 추천 이유와 제휴 여부를 고정 표시 |
| 커뮤니티가 산만해질 위험 | 꿀팁 공유와 Q&A만 남기고 인기 글을 상단에서 먼저 보여줌 |
| 홈과 주기 탭이 중복될 위험 | 홈을 주기 관리의 단일 진입점으로 통합 |
| B2B와 공동 가구가 MVP를 흐릴 위험 | 개인 사용자 문제에 집중하도록 범위에서 제외 |

## 9. 최종 프로토타입 기준

| 커뮤니티 | 반응 좋은 글, 꿀팁 공유, Q&A |
| 마이 | 완료 통계, 최근 기록, 저장한 셀렉션, 청소발자국 |
| 제외 | 주기 탭 분리, 해결/예약 플로우, 지연 카드, 관리자 가이드, 공동 가구 |

## 10. 최종 채택 원칙

1. 서비스명은 확정 전까지 가칭으로만 다룬다.
2. MVP의 핵심 행동은 큰 카테고리 완료와 다음 주기 갱신이다.
3. 사용자가 세부 항목을 입력하지 않아도 시작할 수 있어야 한다.
4. 홈은 주기 관리의 첫 화면이자 중심 화면이다.
5. 셀렉션은 판매 목록이 아니라 브랜드가 고른 좋은 선택지다.
6. 커뮤니티는 꿀팁 공유와 Q&A로 문제 해결에 집중한다.
7. 구매, 예약, 서비스 연결은 보조 경험이다.
8. 공동 가구와 B2B는 이번 MVP에서 제외한다.
