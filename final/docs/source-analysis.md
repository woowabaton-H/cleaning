## 3. 반복되는 공통 방향성

1. 청소 앱의 핵심은 체크리스트가 아니라 `상태 인식 → 해결 방법 → 도구/서비스 연결 → 완료 기록 → 다음 주기`의 반복 루프다.
2. 첫 진입에서 많은 입력을 요구하면 실패한다. 기본 카테고리와 추천 주기가 먼저 있어야 한다.
3. 상태는 정상, 임박, 지연으로 보여주고, 지연에는 빨강보다 분홍/코랄 계열을 써 죄책감을 줄인다.
4. 직접 해결과 맡기기는 동등한 선택지로 제시해야 한다.
5. 용품/업체 추천은 광고처럼 보이면 안 된다. 제휴 여부, 가격 기준, 외부 이동을 명확히 표시해야 한다.
6. 완료 기록은 제품의 핵심 데이터다. 완료 방식별로 SELF, COMMERCE, PARTNER, SUBSCRIPTION을 구분해야 한다.
7. 초기 수익화는 직접 인력 운영이나 자체 물류가 아니라 중개, 제휴, 파트너 구독 연결이 현실적이다.

| 네 개 핵심 탭과 커뮤니티/청소템 분리 | huchu | 최종 IA에 홈, 해결/예약, 주기, 커뮤니티, 마이 구조로 반영하고 청소템은 해결/커뮤니티 흐름 안에 연결 |
| 빠른 해결 시트 | huchu | 지연 카드에서 가이드, 청소템, 예약을 한 시트 안에서 선택하게 구현 |
| Task와 Issue 구분 | if | 기획서 데이터 모델과 프로토타입 데이터 구조에 반영 |
| 자체 구독 크레딧 제외 | if, 테리 | MVP 사업 모델에서 제외하고 파트너 구독 중개로 분리 |
| 접근성 기준과 바텀시트 | if GPT 프로토타입 | Escape 닫기, 터치 영역, aria-live 토스트를 최종 프로토타입에 반영 |
| 주간 클리어 루프 | 몽이 | 홈 상단 진행 카드와 성공 지표에 반영 |
| 알림에서 외주로 이어지는 시나리오 | 몽이 | 예약 플로우의 독립 진입점으로 반영 |
| 청소발자국 히트맵 | 몽이 | 마이페이지의 리텐션 장치로 반영 |
| 브랜드 계층: 클린루프 + 보송이 | 테리 | 서비스명은 클린루프, 보송이는 캐릭터/화자로 반영 |
| 전문가 기준선 | 테리 | 가이드와 예약 플로우에 `직접 가능 범위`와 `전문가 권장 기준`으로 반영 |
| 업체 카드 필수 정보 | 테리 | 견적/매칭 화면에 가격, 가능 지역, 범위, 제외 범위, 후기, 보험, 제휴 배지를 표시 |

## 5. 한 사람에게만 있지만 매우 좋은 아이디어

| 아이디어 | 출처 | 판단 |
| --- | --- | --- |
| 커뮤니티에서 관리자 콘텐츠에만 청소템/서비스 연결을 허용 | huchu | 광고성 커뮤니티가 되는 것을 막는 좋은 안전장치다. 채택한다. |
| 추천 점수에서 제휴 여부를 낮은 가중치로 둠 | if | 신뢰 기반 추천 원칙으로 채택한다. 사용자 화면에는 점수 노출 없이 추천 근거만 보여준다. |
| 주간 클리어 달성률을 리텐션 지표로 사용 | 몽이 | 주기가 긴 청소 서비스의 재방문 문제를 해결하는 지표다. 채택한다. |
| 보송이를 결제/안전/가격 발화에서 제외 | 테리 | 귀여운 화자가 결제를 권하면 다크패턴처럼 보일 수 있다. 채택한다. |
| 유효 주기 계산에 생활/계절/사용자 수정 배수를 반영 | 테리 | MVP에서는 규칙 설명과 수동 수정만 두고, 확장 범위에 개인화 계산으로 반영한다. |

## 6. 서로 충돌하는 방향성

| 충돌 지점 | 원본별 방향 | 최종 판단 |
| --- | --- | --- |
| 서비스명 | huchu/몽이/테리는 클린루프, if는 보송 매니저 | 서비스명은 확장성이 큰 `클린루프`로 통일하고 `보송이`는 캐릭터/화자에 흡수 |
| 커뮤니티 MVP 포함 | huchu/테리는 포함, if/몽이는 축소 또는 후순위 | 커뮤니티는 MVP에 포함하되 관리자 가이드, Q&A, 잡담의 가벼운 목록/상세 수준으로 제한 |
| 청소템 위치 | huchu는 독립 탭에 가깝고, if/몽이는 커머스 탭 또는 키트 | MVP에서는 독립 쇼핑몰처럼 만들지 않고 가이드/커뮤니티에서 연결되는 청소템 탐색으로 둔다 |
| 자체 구독 크레딧 | 일부 중기 아이디어에 존재 | MVP와 초기 사업 모델에서는 제외. 파트너 구독 중개만 유지 |
| 정상/임박 항목 클릭 | 일부 원본은 정상도 상세 접근, 일부는 지연만 액션 | 정상도 정보 확인은 가능하되 핵심 CTA는 지연/예약 항목에만 강하게 둔다 |
| 가입일 기준 자동 계산 | 몽이/테리에서 강함 | 초기 데모와 MVP 기본값으로 사용하되, 사용자가 첫 화면에서 바로 수정/완료할 수 있게 보완 |

## 7. 최종안에서 버릴 요소

1. 자체 청소 인력 운영과 자체 물류 커머스.
2. MVP 단계의 자체 크레딧 구독, 월 5만 원 이상 고정 구독 판매.
3. 사진 기반 AI 진단, 고도화된 자동 판정.
4. 장바구니, 주문, 결제, 배송, 환불까지 포함한 직접 판매.
5. 강한 게임화, 순위 경쟁, 스트릭 끊김 경고.
6. 공포 마케팅, 빨간 경고 중심 UI, 벌레/오염 클로즈업 이미지.
7. 제휴를 추천처럼 숨기는 카드.
8. 정상 항목까지 모두 강한 액션으로 만드는 복잡한 대시보드.

## 9. 최종 프로토타입 기반 선정

기존 프로토타입은 모두 단일 HTML 기반이다. 최종 프로토타입은 별도 빌드 없이 실행 가능한 정적 HTML/CSS/JS로 만들되, 유지보수를 위해 파일을 분리한다.

| 기준 | 판단 |
| --- | --- |
| 기반 기술 | 정적 HTML, CSS, Vanilla JS |
| 참고한 구현 | if GPT 프로토타입의 접근성/바텀시트/주기 계산, 몽이 프로토타입의 주간 클리어/알림/예약 시나리오, if Claude 프로토타입의 단순 데이터 구조 |
| 보완한 흐름 | 청소 서비스의 핵심인 서비스 선택, 공간/평수, 일정, 견적, 전문가 매칭, 예약 확인 |
| 제외한 구현 | 실제 결제, 외부 API, 로그인, DB 저장, 실시간 최저가 |

## 10. 최종 채택 원칙

1. 제품명은 `클린루프`로 통일한다.
2. 핵심 루프는 상태, 가이드, 도구/서비스, 완료 기록, 다음 주기다.
3. 직접 해결과 맡기기는 같은 화면에서 동등하게 제시한다.
4. 커뮤니티는 정보 신뢰와 질문 해결을 위한 공간이며, 광고성 연결을 남발하지 않는다.
5. 청소템은 직접 판매가 아니라 문제 해결 도구 탐색과 외부 구매 연결이다.
6. 예약은 MVP에서 외부 예약/문의 또는 리드 생성으로 처리한다.
7. 모든 가격과 제휴는 투명하게 표시한다.
8. 초기 서비스는 1인 가구와 바쁜 직장인을 중심으로 시작하고, 공동 가구와 B2B는 확장 범위로 둔다.
